# 机构资料全网检索补齐 · 证据留痕与操作规范

- 建立日期：2026-11-07
- 触发需求：真正补齐机构数据，且**不需要任何 API 授权**，改由 WorkBuddy 会话侧技能全网搜索完成
- 技能依据：`multi-search-engine`（16 个搜索引擎，标准网页检索 URL，无密钥）+ `fjhx-fujian-branch-distance`（步骤 7）
- 产物：`intel/org_intel.json`（公开级，注入 H5）、`intel/verify_report.md`（自动校验报告）、`../intel/org_intel_local.json`（会话侧内部级，不发布）

---

## 一、能力边界（须如实说明）

| 事项 | 结论 |
| --- | --- |
| 页面能否在点击按钮时实时调用会话侧技能 | **不能**。静态单文件 H5 运行于微信内置浏览器，与 WorkBuddy 会话进程隔离；无公网后端时无法反向触发会话侧检索 |
| 页面能否直连商业数据库 / 政府登记接口 | **不能**。跨域限制 + 密钥/授权限制 |
| 本方案如何实现「真补齐」 | 由技能在**编制阶段之前**完成全网检索、交叉核验与结构化落盘，构建时内联进页面；页面点按钮时调取已核验事实并渲染，进度条反映真实的本地阶段 |
| 是否需要 API 授权 | **不需要**。页面零凭据、零外部网络请求；检索发生在会话侧，使用公开网页与搜索引擎，无密钥 |
| 未收录机构如何处理 | 如实标注「资料库未收录」，按行政区划中心近似测算；不以模板内容冒充核验结果 |

## 二、检索式矩阵（本批实际执行）

按字段族组织，中文查询走国内引擎（百度 / Bing CN / 360 / 搜狗），必要时以 `site:` 限定官方域名，并以 `WebFetch` 抓取官方页面原文。

| 字段族 | 检索式示例 | 来源类型 |
| --- | --- | --- |
| 机构全称 / 性质 / 级别 | `site:gov.cn <机构名> 机构职能`、`"<机构名>" 是省政府组成部门`、`site:pbc.gov.cn <机构名> 简介` | 政府门户「机构职能 / 机构概况」 |
| 主要职责 | `site:<官方域名> <机构名> 主要职责 内设机构`、`site:gov.cn <机构名> 职责` | 官网职责页、「三定」规定 |
| 内设机构 | `site:<官方域名> <机构名> 处室单位 直属单位`、`<机构名> 机构设置 内设机构` | 官网「机构设置」「处室单位」栏目 |
| 上级 / 下属单位 | `<机构名> 部门预算 单位构成`、`site:gov.cn <机构名> 预算公开`、`site:<官方域名> <机构名> 分支机构` | 部门预决算公开、官网直属单位清单 |
| 负责人（内部级） | `site:<官方域名> <机构名> 领导简介 分工`、`site:<官方域名> <机构名> 2026 会议 主持` | 官网领导之窗、最新官方报道 |
| 统一社会信用代码 | `"<机构名>" 统一社会信用代码`、`site:gsxt.gov.cn <机构名>` | 公开主体信息页（以国家企业信用信息公示系统为准） |
| 地址 / 区划 / 坐标 | `<机构名> <地址关键词> 经纬度 坐标`、`<机构名> 通讯地址 邮政编码` | 官网机构信息页 + 公开地图 POI（两来源交叉） |
| 时点复核 | `<机构名> 2026 报道`、`site:<官方域名> <机构名> 2026` | 最新官方新闻、预算公开、任免报道 |

**交叉核验规则**：机构性质、职责、内设机构、上下级单位以官方门户原文为第一来源；第二来源（预算公开 PDF、官方新闻、公开主体信息页、公开地图 POI）用于复核时点或口径差异。非官方百科仅作辅助参照，**不单独作为 `verified` 依据**。

## 三、字段状态与禁止事项

| 状态 | 含义 | 页面呈现 |
| --- | --- | --- |
| `verified` | 官方公开页面直接载明 | 写入材料，附来源 |
| `cross` | 两个及以上独立来源一致 | 写入材料，注明交叉 |
| `partial` | 官方原文摘录取其要点 | 写明「完整条款见来源」，不补写未展示内容 |
| `conflict` | 来源口径/时点不一致 | 并列列示，不合并推定 |
| `unverified` | 未检索到公开可核验信息 | 留空并如实标注，**不以同类机构通行架构填充** |

禁止事项：不臆造负责人姓名与任免、不推断行政隶属与业务指导关系、不把「研判」写成「已核验」、不引用转载汇编作为唯一依据、不写入核心财务指标与预期成效、不使用禁用机构名。

## 五、信息分级（合规）

- **公开级** `intel/org_intel.json`：仅机构层面公开事实（全称、性质、代码、地址、区划、坐标、主要职能、内设机构、上下级单位、证据 URL），注入公开 H5。
- **内部级** `../intel/org_intel_local.json`：官网公开的领导姓名、职务分工与办公联系方式，仅用于会话侧生成正式《业务合作参阅材料》，**不注入公开页面、不上传第三方云、不随 GitHub Pages 发布**，全文标注「行内参考 请勿外传」。
- 自动校验：`verify_index.js` 第 7 部分遍历内部级全部领导姓名，断言公开级文件与页面均不含该姓名。

## 六、按需补齐 SOP（新增机构）

1. 在 WorkBuddy 会话中指定机构名称，发起「全网检索补齐 <机构名>」。
2. 按第二节检索式矩阵逐字段检索；关键字段至少双来源交叉；抓取官方页面原文留痕。
3. 将结果按 `fjhx-org-intel/v1` schema 写入 `intel/org_intel.json`；涉及自然人姓名写入会话侧 `../intel/org_intel_local.json`。
4. 执行 `python intel_pipeline.py` 强校验（来源可追溯 / 状态合法 / 坐标包围盒 / 无占位符 / 无禁用词）。
5. 执行 `python build_index.py && node verify_index.js && python verify_browser_cdp.py`。
6. 重新部署两条线上链接；页面刷新后自动命中新机构。
7. 更新 `intel/verify_report.md` 与 `SKILL.md` 收录清单。

## 七、与旧方案对照

| 维度 | 旧方案（腾讯位置服务 JSONP） | 本方案（技能全网检索补齐） |
| --- | --- | --- |
| 页面凭据 | 内置地图 Key（网络请求仍可见） | 无任何凭据 |
| 外部请求 | 每次查询 + 每次编制各一次 | 零 |
| 可补齐字段 | 仅规范名称、地址、区划、POI 类别 | 全称、性质、代码、职责、内设机构、上下级、坐标、证据 |
| 负责人 / 内设机构 | 一律「待核实」 | 机构层面事实已核验；姓名按分级口径留于会话侧 |
| 失败模式 | 接口超时需降级 | 无网络依赖，不存在接口失败 |
| 可复核性 | 接口返回无留痕 | 逐字段附来源 URL、日期与口径差异 |
